## Required core bridges

- `M3-attribute-metadata`, after contracts: explicit defaulted flags for complete/incomplete attribute events; prerequisite of callbacks.
- `M3-async-resources`, after attribute metadata: suspendable async resource and cleanup boundary; prerequisite of SAX/push/reader and async transport. Writer remains independent.

- `M3-streaming-pump`, after callbacks and async resources: shared bounded decode/event aggregation; prerequisite of SAX/push/reader and async transport.

- `M3-async-token-binding`, after contracts: owning session bridge requested during async-resource work; integrate before that worker consumes async rebinding.

## Parallel lanes

Tasks with disjoint ownership and satisfied prerequisites can run concurrently. These topological waves show the internal joins; external prerequisites in the table still apply.

- Wave 1: `M3-contracts`.
- Wave 2: `M3-attribute-metadata`, `M3-writer`.
- Wave 3: `M3-callbacks`, `M3-async-resources` (writer may continue).
- Wave 4: `M3-streaming-pump`; independent `M3-async-writer` may start after writer verification.
- Wave 5: `M3-sax`, `M3-push`, `M3-reader`.
- Wave 6: `M3-async-input` after SAX/reader; `M3-async-serialization` after async writer; then `M3-async` join.
- Wave 7: `M3-corpus`.
- Wave 8: `M3-gate`.

## Additive exit

Verify usable standalone core preview with callback examples and measured streaming allocation report.

No dependency may point to a later milestone. Earlier checks stay required. A gate verifies the integrated combination, including functionality from the preceding gate. In-progress branches and public stubs cannot satisfy it.

## Ownership and integration

Each task lists its source, tests, API fragment, and report ownership. Shared contract changes finish first. Branch workers update only their own task record; the coordinator verifies integration before unlocking dependents. See the [workflow](../tasks/README.md).
