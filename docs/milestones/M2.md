## Parallel lanes

Tasks with disjoint ownership and satisfied prerequisites can run concurrently. These topological waves show the internal joins; external prerequisites in the table still apply.

- Wave 1: `M2-contracts`.
- Wave 2: `M2-streaming-allocation-probe`.
- Wave 3: `M2-pi-allocation-probe` joint verification.
- Wave 4: `M2-resolver`, `M2-encoding`, `M2-dtd-framing`, independent `M2-dtd-model`.
- Wave 4 repair/join: `M2-resolver-allocation-probe`, then `M2-encoding-allocation-probe`, then `M2-tree-allocation-probe`, then renewed `M2-dtd-framing` verification.
- Wave 5: `M2-dtd-values`, then `M2-dtd-parser`, then `M2-dtd-grammar` verification join.
- Wave 6: `M2-dtd`.
- Wave 7: `M2-entities-foundation`; `M2-dtd-composition` repair must verify before dependent tightly coupled `M2-entities` external composition.
- Wave 7 repair: `M2-resolver-cancellation` preserves changing per-call tokens before entity composition verification.
- Wave 7 allocation repair: `M2-dtd-framing-allocation-probe` must verify before renewed `M2-entities` full checks.
- Wave 8 normative repair: `M2-version-contract` may run alongside profile classification; verified contract then unlocks `M2-version-declarations`, which must verify before grammar execution.
- Wave 8 entity-base repair: verified profile unlocks `M2-dtd-entity-base`; its Parser subtree avoids the active declaration repair and must verify before grammar.
- Wave 8 DTD validity repair: verified entity-base repair unlocks `M2-dtd-nonvalidating`; six PE validity-only gaps must be corrected without weakening declaration-boundary well-formedness before grammar.
- Wave 8 unresolved-reference contract: `M2-undeclared-contract` independently freezes E13 identity/diagnostic/DOM behavior; verified contract then unlocks ordered `M2-undeclared-content` after declaration and DTD validity repairs; actual event/DOM/refusal evidence must verify before grammar begins.
- Wave 8: `M2-conformance-profile`, then `M2-conformance-grammar`, then original `M2-conformance` complete-profile integration join.
- Wave 9: `M2-recovery`.
- Wave 10: `M2-gate`.

## Additive exit

Verify complete strict profile and separately documented recovery, including malicious-input resource constraints.

No dependency may point to a later milestone. Earlier checks stay required. A gate verifies the integrated combination, including functionality from the preceding gate. In-progress branches and public stubs cannot satisfy it.

## Ownership and integration

Each task lists its source, tests, API fragment, and report ownership. Shared contract changes finish first. Branch workers update only their own task record; the coordinator verifies integration before unlocking dependents. See the [workflow](../tasks/README.md).
