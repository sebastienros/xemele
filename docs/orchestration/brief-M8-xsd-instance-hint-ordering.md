# M8 instance hint ordering — accepted bounded design

Root, independent contract/XPath reviewers and the read-only main orchestrator agree this repair fits the existing complete XSD1.0 Second Edition project profile. No-fetch disables acquisition, not instance hint-order checking. General W3C minimally conforming processors need not implement every web-aware facility (§2.4); the project's broader profile and its declared exclusion only of fetching guide this choice. Rule4 of Structures§4.3.2 and W3C4078 preserve the seven original INVALID expectations. W3C9158 is an unadopted backport, not authority to change them. Exact source/status/hash records are in `M8-xsd-instance-hint-ordering-triage.json`.

The task depends on verified content-failure assessment before editing its evaluator hook. Own only new `Evaluation/SchemaHints.cs`, minimal `Evaluator.cs` Enter integration, its new decision and standard task paths. Do not edit Values.cs, change public/frozen interfaces, fetch hints, mutate instances, merge unverified peer code or redefine source oracles. Record this project interpretation in the owned decision before runtime edits.

Maintain per-validation ordinal identity of namespace names used by earlier physical element or attribute names. Treat each start tag atomically: check all hints against the preceding-tags set, then record the current element and every physical attribute namespace. First-use hints on the same tag are timely regardless of attribute order. Names on ancestors or previous siblings make hints late. Empty namespace is a real key, including prior unqualified attributes. Namespace declarations, prefixes mentioned only in QName values and namespace/location tokens inside hints do not themselves count as use. Repeated hints before first use are timely; a repeated identical location after namespace use is still late. Check all namespace/location pairs and emit one ordering diagnostic per offending hint attribute at its original location.

The explicit project interpretation applies this global ordering bookkeeping throughout the validation-root subtree, including skipped nodes. It does not turn on datatype/content/lexical assessment for skipped nodes, change skipped xsi:type/nil behavior, or make an upstream-conformance claim for the unadjudicated skip corner. Keep typed attribute values and identity hooks exactly once. This interpretation follows rule4's global wording; reviewers found no independent W3C clarification resolving its interaction with wildcard skip.

Use borrowed spans and XML whitespace tokenization, with charged scans/comparisons and bounded per-run table growth before allocation. Borrow existing DOM namespace strings where possible; retain no location-token strings or fabricated components. Poll long loops even when caps are null. Do not double-charge DocumentCharacters for the extra scan. Retain revision/mutation, cancellation, diagnostic and shared work semantics. No static per-document state.

Required proof: seven unchanged originals using the original first-hint schemas explicitly compiled, all complete invalid; preserve prior original failures/adapter limitations as history. Independent same-tag permutations, attribute-only/empty namespace use, declarations/QName values not-use, repeated/multiple hints, chosen skip policy and preserved skipped constraints, lexical errors, content-failure recovery, stable source locations, zero resolver calls, exact/one-short work/diagnostic limits, long-token/comparison cancellation including null caps, repeat/concurrent isolation and document immutability. Use existing API/consumer/check/allocation support. No counters until a fresh root grant. Corpus changes only after this repair is integrated and verified, and must expose actual product assessment separately from BCL outcomes.
