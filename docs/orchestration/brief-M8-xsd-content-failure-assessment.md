Root and independent contract source review found a concrete failure-path defect in `Evaluator.cs` (SHA256 `ca7c7f31f93dc841ee081daa99139ae25eb2e7b36f56c66b8ec8a3fa547f6af8`). `Accept` sets null/Strict outputs before it permanently latches failure; those outputs on false do not identify a successfully matched strict wildcard. The evaluator nevertheless emits repeated content and undeclared-element errors. Counted matcher source `4a3a93ee255aec5be689445031e8cd91b590724c` now completes seven of ten exact originals, but Z034_a2/a3/b exceed unchanged Diagnostics1024 after correct initial semantic rejection. Their actual outcomes at `905ab9022c4dd61f2443ecc80226ce2435511359` remain failures (outcome SHA256 `5e41c54cbed27a7e7f85dbdff0e99d6647449782081295ff369c67ad94018319`).

The separate repair starts from verified facade code and owns only `Evaluation/Evaluator.cs` plus its own test/report/benchmark paths. Do not consume the unverified counted matcher. Prove independent simple witnesses first, integrate and verify this repair, then the counted matcher owner adds the dependency and reruns its ten unchanged originals under the complete recorded corpus policy. The gate explicitly requires this repair.

Use one run-local `Frame.ContentFaulted` boolean, separate from `Frame.Valid`. Until faulted call `Accept` and retain the existing poll. After first semantic false, set the parent invalid/faulted, emit one content error at that child and ignore both outputs. That child and subsequent siblings bypass only this parent cursor: assess a global declaration when available, otherwise retain existing global `xsi:type` or open-anyType assessment without a fabricated strict requirement. Never set subtree skip or infer a local declaration by name. At parent exit omit only the already-failed cursor's redundant Complete call. An unfaulted cursor still reports missing content. A successful strict wildcard match still requires a declaration or globally resolved type. Attribute invalidity must not fault the content cursor; each descendant has its own state.

Continue all traversal, attributes/defaults/fixed values, identity hooks and final identity/IDREF checks. Parent remains invalid. Completion still requires traversal and final checks to finish without refusal. All caps and cancellation behavior stay unchanged; no global diagnostic filter, reset budget, raised limit, caught cancellation or forced completion. Remaining operations retain charged work and polling, including null caps. Removed calls do not require artificial charges.

Required proofs: over1024 harmless unmatched siblings finish complete-invalid under Diagnostics1024 with one content failure; later known child datatype/required/fixed/content errors and unknown child global xsi:type; later genuine strict wildcard failure; independent parents and unfaulted incomplete sequence; attribute error before a valid content match; balanced ordered identity hooks and later key/keyref/duplicate-ID/unresolved-IDREF; real independent diagnostic exhaustion; exact work/depth/token/document boundaries, cancellation during recovery with null caps, caller exceptions, mutation and repeat/concurrent isolation. Reuse existing infrastructure; source-review allocation probe before preparation and obtain fresh root lease before any counters. No throughput claim from correctness deadlines.

The assessment continuation is an implementation inference from [Second Edition §3.3.4](https://www.w3.org/TR/2004/REC-xmlschema-1-20041028/#cvc-assess-elt): absent particle attribution, known global declarations or xsi:type permit assessment, otherwise the ur-type permits lax assessment. It does not restore the rejected parent's validity. Source/design review itself is not runtime evidence.
