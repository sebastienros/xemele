# CSS selector implementation and preparation

The compiled program owns decoded names, resolved namespace constraints, compounds,
combinators and normalized nth progressions. Matches borrows current node names and
attribute values, traverses links without constructing an iterator/result collection,
and uses graph-specific expanded-name comparisons. Select owns a read-only array
membership snapshot; retained nodes keep permanent graph owners and expose later mutation.

The focused matrix uses actual XmlDocument/XmlNode and HtmlDocument/HtmlNode graphs.
It covers accepted grammar, unsupported-feature offsets, ASCII versus XML case rules,
namespace snapshots, expanded-name type positions, escapes, comments, PI/CDATAs,
detached nodes, empty documents, immutable results and mutation visibility.

Performance preparation mechanically routes the verified M7-html-model freeze,
prepare_identity and run_measurements lifecycle into task-owned CSS paths. Original
model lifecycle files remain unchanged. The planned maxima are 35 s initial identity,
60 s allocation, 900 s NoEmit benchmarks, 35 s final identity, plus 70 s conservative
cleanup for the four owned process handles: 1100 s total. Every failure path attempts
product/identity group cleanup, reap, final identity, and scoped no-child checks.
The exact wrapper's identity-only mode executes no product measurements. The full
child environment receives an opaque SHA-256 and opaque per-key hashes, including
CODEX_THREAD_ID; SHLVL is fixed to 1. Source, generated files, binaries, local corpus,
SDK/runtime and host are frozen. No raw result inspection occurs during a lease.

The 29 prepared ShortRun/MemoryDiagnoser cases compare the actual production
class-token loop (bound once by a cached reflection delegate) to an allocating
CSS-whitespace split oracle, cached SearchValues, and span IndexOfAny. Inputs cover
short and long values, early and middle hits, misses, ASCII, multilingual names,
CSS whitespace non-CSS NBSP, a short miss and dense delimiters. The remaining cases execute current matches,
owned query/result snapshots on both graphs, and owned compilation. Allocation
probes separate cold compile/static initialization, positive controls, warmed
borrowed Matches and token scanning, owned compilation, XML/HTML query results,
and inclusive retained result snapshots with owners. Discovery is not measurement.

The W3C cache was read only. All 3386 manifest-listed resources were copied by
regular file copy to ignored worktree corpus paths with the xmlconf prefix; each
source and copied file was SHA-verified. No refetch, cache edits, or symlinks.

Validation limitations: two restricted test restores stalled and were terminated
by their exact process groups, reaped with exit 137; one restricted test build was
park-interrupted and reaped with exit 137. Scoped inspection confirmed no children.
The subsequent elevated cached-source restore and focused build/test succeeded.
An initial API compare selected host dotnet without runtime 10.0.11 and failed;
rerunning with pinned dotnet on PATH succeeded. Probe compilation initially used
an incorrect BDN run overload, corrected before discovery. None of these failures
is represented as a passing check. Timing/allocation evidence remains pending an
exclusive coordinator grant. Only Arm64 is available locally; x64 validation is
not claimed.
