# Scope and code review

Implementation under review: `87d101c7e9b09167b2d114f1f33ea5974680617d`.

Only `experiments/Input/` and `docs/reports/M0-input-spike/` implement the experiment. The task record is the only coordination/status file edited. No library, public API, shared solution/project configuration or peer implementation is required. `M0-build` is verified at integrated revision `c7ecb084050b8c4cc014e7bc3f4b57f37f34413e`, which is an ancestor of the claim and implementation. Experiment references centrally pinned BenchmarkDotNet only; it does not reference later milestones or an unmerged branch.

Coordinator review found repeated full-tail delimiter searches in the initial revision; the correction bounds each search to quantum+1 units and adds one-chunk 1 MiB progress/boundary tests. Old affected timings are superseded; corrected input/rejection timings refer to the corrected revision, and unchanged primitive-suite evidence retains its original tested revision. The scanner owns two booleans. The sink owns Unicode carry/decoder state, with borrowed callbacks and bounded stack scratch. `Consumed` advances before a callback pause, so the caller cannot replay delivered input. Final incomplete tokens get one end callback and can pause before completion. Whole conversion baselines explicitly own their returned array/string. Candidate matching stores at most ten units, uses an overflow flag and requires an end marker. Exact/ASCII-insensitive rules fold only A–Z; hashes always verify full equality and length. A deliberate same-length hash collision and randomized unknowns are checked against a separate ordinal ASCII reference.

Strict UTF-8 decoding and UTF-16 surrogate checks run on every payload path. ASCII token framing itself is synthetic and unambiguous in valid UTF-8; this does not replace XML name/scalar rules. The core does not implement source locations, grammar, attribute/event models, entity handling, normalization, cancellation, reentrancy/faulting, I/O or DOM persistence. Those remain assigned to their owning contracts and production tasks. A decoder-first character scanner and a byte-framed scanner therefore remain candidates, rather than frozen runtime decisions.

Allocation measurements explicitly distinguish cold setup, short warm counter batches, long warmed BDN execution, and source retention. IL can prove static-data or heap-array lowering, but inlining/stack allocation/scalar replacement can remove a consumer's allocation later. Constant extraction and tiny literal matching can approach an empty benchmark; no timing advantage is inferred from those numbers. Invalid-input exceptions are separately measured and are allowed to allocate.

Required follow-ups: M0-contracts reviews representation/consumption/lifetime decisions using both experiment lanes. M1-input/M1-syntax/M1-dom remeasure composed XML correctness, decoding/locations, realistic callback costs and token limits. Broader vocabularies/generated hash candidates need their own same-semantics comparison. x64 and arm64 repeatability evidence is required before release performance claims. No request to change a shared path is needed for this experiment.
