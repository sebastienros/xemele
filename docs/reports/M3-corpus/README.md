# M3 corpus preparation

The public original-byte lane runs all 2,585 cases in the unchanged M2 applicability ledger. DOM supplies the content oracle; SAX supplies the additional public streaming metadata oracle. Synchronous byte/stream SAX, asynchronous SAX, deterministic random-chunk push, synchronous pull and asynchronous pull agree on acceptance or structured rejection codes. Accepted output compares expanded names, ordered attributes and namespace declarations, incomplete attribute parts, unresolved references at their original child boundary, comments/PIs, and separate CDATA boundaries. Text fragments are coalesced between semantic boundaries. Document-level whitespace is omitted to match the public DOM. Streaming metadata separately compares declaration, effective DTD projection, default provenance and incomplete default declarations. The DOM does not expose all these fields.

No-primary-base public API outcomes are distinct from the M2 conformance oracle supplied with the real source URI. No original is transformed or excluded. The report counts all outcomes, source-context expectation differences, and primary-base denials before resolver invocation. The coordinator must rerun the existing M2 real-source-context lane during integration because the M3 prerequisite closure changes core parsing.

The small independent BCL reader lane checks complete supported namespace, lexical, entity and DTD-default content. Fuzz entrypoints deliberately copy borrowed views; these semantic sinks are excluded from the memory experiment. The fuzz project's owned Streaming folder contains identical standalone oracle source copies, because changing its project to reference another test project is outside task ownership. Compare both copies byte-for-byte when changing the oracle.

## Generated memory experiment

`Runner/Runner.csproj` is a task-owned executable linking the standalone fuzz entrypoints. The generated profile is recorded in `tests/corpora/streaming/generated-profile.json`: exactly 1 GiB UTF-8, depth two, fixed vocabulary, 4 KiB repeated blocks and maximum text token 4,089 characters. It never stores the generated document. The sink counts events/text and samples a full collected managed live heap every 16 MiB while parsing, and at completion. Absolute whole-heap live bytes conservatively upper-bound parser-owned live bytes: source/sink/runtime objects are included without subtracting them. The gate is 8 MiB. Cumulative allocation and process RSS are separate fields; nonpositive platform RSS is null/unavailable. External `/usr/bin/time -l` reports RSS separately.

Each mode asserts exact bytes, text count, start/end counts, one completion and first start before source exhaustion/EOF. Controls use 1 MiB; `negative` adds a retained 9 MiB managed object and must fail the same live-byte threshold while the harness exits successfully upon detecting that failure. Timing is informational on the shared Arm64 host. The exact five large modes are sax, sax-async, pull, pull-async, push. Large runs require coordinator's measurement scheduling grant.
