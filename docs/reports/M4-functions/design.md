# Core function library boundaries

XPathCoreFunctions implements only IXPathFunctionLibrary against the verified M4 model, with the exact immutable XPathCoreSignatures metadata. There is no compiler, navigator, evaluator, facade, extension dispatch, live topology read or later-milestone dependency. Its standalone friend sample has its own navigator fake; no new public surface is added.

Invocation checks metadata, all arities, focus, argument and return limits. Work is charged against the caller's shared budget for inspected argument/node/identity entries and scanned/copied UTF-16 units. Every scan/match/transform polls per charged unit. String conversions preserve the model's invariant numeric grammar. Decimal parsing validates the whole input with per-unit polling, then sends at most 1100 significant digits plus a sticky nonzero tail and exponent to the runtime parser. Binary64 rounding boundaries terminate within 1075 decimal places, so this preserves exact halfway/tail decisions while bounding the runtime primitive independently of input length. Tests include the half-minimum-subnormal, halfway at one with a nonzero tail over 2000 digits later, and deterministic long-input comparisons. Conversions use bounded stack formatting for round-trip binary64 numbers and exponent expansion before owned string allocation. Formatting has no temporary managed round-trip string. XPath round avoids the incorrect floor(value + .5) rounding at the representable value immediately below .5. Strings have scalar semantics, XML-S normalization/tokenization, first-occurrence translate mappings and Unicode-safe substring boundaries. Invalid surrogate input is rejected with XPATH-TYPE.

Matching uses straightforward charged ordinal comparison loops. No SearchValues, hash token matcher or custom SIMD is introduced without comparison evidence. Transform sizing occurs before string.Create allocation; writing callbacks are static and poll/charge each copied unit. Concat conversion strings, final strings and id tokens are capped before growth. Lists are preflighted for each new logical entry; sorted insertion charges identity/order comparisons and shifted/copied entries. id consumes every node-set string, splits only XML S, deduplicates and orders through its snapshot navigator, then FromSnapshotNodeSet makes an owned result without live rereads. Navigator callback exceptions propagate by identity, including engine-shaped exceptions and cancellation exceptions.

Borrowed numeric/boolean/string-length/search primitives should have zero warmed allocations with preallocated arguments, focus, navigator and budget. Owned conversions/transforms/node sets, initialization and diagnostics are separately measured. Measurements remain pending an exclusive coordinator grant; tests never call allocation counters. Tests use only owned snapshot fakes and run each of the 27 frozen inventory vectors, all arities, scalar/item/conversion cases, exact/one-over shared operations and string/node-set limits, and mid-scan/copy/callback cancellation. Composition conformance, actual navigator ID inference and end-to-end query performance remain their task owners' work.
